需求说明 v2.4 需求文档

本页做什么：作为任务主页面展示探索任务、自动下发链路和安全回退；支持暂停、结束与断点续跑；按排程自动下发并归档；执行中每 5 秒刷新状态，列表页不自动刷新。首次开始执行在策略制定页完成。

本页不做：不提供探索下发策略、手动下发或线上手动兜底；自动下发条件不满足时拦截执行并提示按线下 SOP 处理。

数据逻辑 v2.4 需求文档

关联模块：按设备类型同时下发 + 换批次回基准（8.2）

  • 每个排程步由系统自动向一类设备的所有开机实例下发相同设定值；页面不提供手动下发按钮。
  • 表格中每行一个排程步：目标值对应可写入的下发测点（设备类型级同一设定值）；实际反馈对应各实例的反馈测点（按台罗列）。二者测点不同，须区分展示。
  • 反馈测点数值可点击，打开与柔性/全局寻优同款的历史趋势弹窗，查看该对象反馈测点时序（可对照下发目标曲线）。
  • 换批次回基准（强制）：当前批次全部完成（或因温差保护提前结束该批次）后，须先将该被探变量回送至基准线设定值并确认到位，再开始下一批次。例：冷冻泵扫完 → 冷冻泵回基准 → 再探冷却泵。未回基准不得开下一批次。批次间横幅提示本规则。
  • 历史数据比对已覆盖且未强制勾选的工况点，在策略制定阶段即被排除、不进入排程，因此本表不会出现这类行——排程从基准值之后的下一步开始。
数据逻辑 v2.4 需求文档

关联模块：调整幅度检查（8.2）

每步下发到位后，比较「应执行步长」（本步目标值 − 上步目标值）与「实际步长」（各实例反馈值变化量），二者之差的绝对值须 ≤ 允许偏差；否则视为跳变/漏步，停止下发并告警留痕。

设备类型控制量默认调整步长连续性允许偏差
冷冻泵 / 二次泵频率2 Hz± 2.0 Hz
冷却泵频率2 Hz± 2.0 Hz
冷却塔频率设定2.0 Hz± 2.0 Hz（水冷场景另受最低冷冻冷却温差校验）
冷水主机冷冻出水温度设定0.5 ℃± 1.0 ℃

例：应执行 +2 Hz、某实例实际反馈为 -0.5 Hz，二者偏差为 2.5 Hz → 超出 2.0 Hz 容差，停止下发并告警留痕。

数据逻辑 v2.4 需求文档

关联模块：定时采集与归档

  • 计时起点：本步目标值下发成功并确认到位；
  • 采集时间：等待本次 run 快照的统一间隔时长，默认 15 分钟；
  • 到时动作：立即采集一次实际反馈，并查询绑定仿真模型的最新结果；
  • 归档推进：保存实际值、预测值、目标值、采集时间和主动激励来源，成功后进入下一步；
  • 不再判断：不计算连续采样窗口、极差阈值或稳态状态。采集失败时当前步骤不记为已记录，任务进入暂停。

等待期间仍持续执行开机组合、自动下发链路、水冷最低温差和安全回退监测；本次简化仅移除稳态判断。

边界与异常 v2.4 需求文档

关联模块：运行期持续监测规则

持续监测：① 开机组合漂移；② 自动下发链路异常；③ 水冷系统任一相关主机冷冻冷却温差 ≤ 策略配置下限。任一命中均停止后续自动下发并进入暂停；风冷系统不执行第③项。

交互说明 v2.4 需求文档

关联模块：自动下发推进方式

本期仅支持自动下发：当前步骤达到统一间隔后直接定时采集归档，成功后系统自动下发下一步；采集状态不单独占用表格列。采集失败或安全校验不通过时暂停，不降级为页面内手动下发。

数据逻辑 v2.4 需求文档

关联模块：排程明细与执行状态流转（需求 §6.8）

本区每一行对应开跑时已勾选的一个工况点。行内序号、目标设定值与策略制定页保持一致；步骤执行状态共四态（待执行 / 执行中 / 已记录 / 执行失败）；已记录行提供「验证」：

  • 待执行 → 执行中 → 已记录：按批次内序号由系统自动流转，仅「下发到位 + 采集 + 归档」全部成功才置「已记录」；
  • 执行失败：步骤自身失败后置「执行失败」，任务进入暂停；主表只显示状态，失败原因与当时反馈值在下发记录详情查看；
  • 人工暂停：当前步骤继续完成采集归档并置「已记录」，完成后任务进入暂停，后续步骤保持「待执行」；温差命中 / 安全回退仍即时中断并将当前步骤退回「待执行」；
  • 断点续跑：有失败步骤时优先重试，否则从下一待执行步骤继续；已结束任务不可续跑；
  • 行内「验证」：仅「已记录」展示；点击进入该归档点的验证详情页（需求 §9），直接展示对比结果；
  • 历史数据比对被排除的工况点不进入排程，本表无对应行。
