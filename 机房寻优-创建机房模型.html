版本信息

当前版本：v1.9

更新日期：2026-04-16

变更概述：

  1. 通道封闭模式前置：机房基础信息新增必填「通道封闭模式」，在步骤 1 即确定后续分组生成规则（含无封闭时仅保留一个冷通道分组）；所选模式通过 localStorage 传递至步骤 2。
  2. 空调单独关联：设备信息区收敛为「空调设备信息」，通过「关联空调」弹窗勾选实例；候选数据为所选空间—机房内设备，并按物模型过滤为末端空调及其子模型。
  3. 气流组织阈值：步骤 1 配置冷/热通道温湿度与送回风等全局阈值；无封闭时「热通道温度上限」置灰不可用。
  4. 通道分组与归属：按封闭模式生成分组并支持关联传感器与机柜；冷通道分组下关联的传感器须将通道/位置类属性选为冷通道，热通道分组下由系统自动置为热通道；分组配置为步骤 1 必审项，决定诊断粒度能否到通道/区域级。

本页说明：多步表单第一步；顶部面包屑导航；底部「下一步」校验必填后跳转步骤2，「取消」回列表不落库。

版本信息 v2.8

v2.8（2026-09-08）：对应《末端寻优设备能力抽象架构设计方案-v2.8定稿版》§3.3、§3.4、§4.7、§4.9。①「气流组织信息」的冷 / 热通道温度上限即柔性的需求侧约束：柔性按每条通道近一个窗口的峰值离上限还剩几度决定省电还是增冷，热通道上限与冷通道上限取小；这里配的是机房级缺省，步骤 2 的传感器行可按传感器覆盖（可选）。②「送回风温差下限」即算法的未做功温差阈值 ΔT_idle：运行中送回风温差不超过此值连续两个快照判为压缩机未做功。③数据质量类判据（呼叫无冷升级轮数、数据过期倍数、大面积离线占比等）不进配置页，用全局缺省。

字段说明 v2.8 需求文档

关联模块：气流组织信息 — 冷 / 热通道温度上限、送回风温差下限

冷通道温度上限 Tc,max：必填。柔性寻优的核心约束：每条冷通道近一个窗口内的峰值距此上限不足「请求阈值」时增冷，全部富余时省电，最新值越过此上限时大步增冷；加减机也用它判真热点。机房级缺省，步骤 2 的传感器表可按传感器填写覆盖值（可选）。

热通道温度上限 Th,max：封闭模式下必填。与配对冷通道的裕度取小后进入柔性，超上限同样触发增冷。须不低于冷通道上限；建议按机柜典型温升设置（如冷通道上限 + 10～12℃），设得过低会迫使空调为热通道过冷冷通道。无封闭时置灰。

送回风温差下限（未做功温差阈值 ΔT_idle）：必填，缺省 2℃，范围 1～4。运行中空调送回风温差不超过此值、连续两个快照 → 判为「开着但压缩机没在制冷」，两引擎据此处置空转 / 掺混机组。原字段沿用，含义即算法的 ΔT_idle。

冷通道湿度上 / 下限：监测告警用；露点由算法按温湿度自算，不读这两个值。

不在本页配置的判据：呼叫无冷升级轮数、未做功确认快照数、数据过期倍数、大面积离线占比等数据质量判据用全局缺省，不出现在配置页（文档 §3.5）。

校验：热通道上限 ≥ 冷通道上限；送回风温差下限 1～4℃；不满足时输入框标红。

数据逻辑 v2.9 需求文档

关联模块：空调设备信息 — 属性真源、「属性存在即显示」与主控制变量分派（属性填写 / 按设备自动适配 / 缺数据处理）

  • 真源：铭牌与设计点的真源是物模型实例属性（标准物模型 xlsx 静态数据 sheet 定义、后台 DTDL 同步），热力模型不另存一份。本页打开、关联空调回写时按实例当前值带出；在本页改的值随热力模型保存（步骤 2「完成」）写回该设备实例的静态属性，设备管理里看到的是同一个值（2026-10-31 调整：页内直接编辑，不再跳转维护）。
  • 型号去掉（2026-10-31 评审）：属性区不再出现 modelNumber；迁移分组键改为设备类型 + regulationType + 铭牌组合（air_volume + refrigerating_capacity），见需求文档 §4.1。
  • 按设备自动适配：渲染只看「该实例的对象类型有哪些属性定义」，不按水冷 / 风冷写死行：风冷型自然出 regulationType / compressors_num / cop，冷冻水型自然出 5 个设计点；同一机房风冷型与冷冻水型混合编队各按自身类型渲染（示例 1#、2# 风冷型；3#、4# 冷冻水型）。后续加属性只改物模型，页面不改。
  • 同一规则适用的其他页面：柔性寻优页规则表行、平面图标签、安全边界页末端变量行同样按对象类型与已绑可写点位生成；安全边界创建 / 编辑两页本次只加一条 v2.9 批注指向本页，不重画。
  • 主控制变量按 controlMode 分派（按设备自动适配）：属性区底部「主控制变量」由 controlMode 派生：0 → 回风温度设定 4_25_0；1 → 送风温度设定 4_27_0；风冷型与冷冻水型同一规则，不拆对象类型。controlMode 缺省时按绑点推断（有 4_27_0 历史为送风温控，否则回风温控）并提示确认（§4.1）。
  • 辅助通道按可写点位：「辅助通道」列出该实例已绑的可写点：风机转速上限设定 4_90_0（风冷 / 冷冻水均有）、水阀最大开度设定 3_2001_0（冷冻水型；1_4_0 水阀开度是反馈读点，不是控制通道）。寻优候选通道 = {启停、主温度设定、风机上限、水阀上限} ∩ 该实例已注册可写能力，其余通道冻结当前值（§8.2）。
  • 存量项目：存量冷冻水项目升级后设计点为空，本页显示缺失标红但不拦保存；保存后在「机房模型校验」页记 INPUT_MISSING 移出可动作集，机房其余设备照常寻优、不阻断（示例 4#空调）。

产品说明 v1.9 需求文档

关联模块：通道分组配置

通道分组配置是本期新增重点，用于明确诊断分析颗粒度。系统先根据封闭模式生成基础分组结构，用户再分别为每个分组补充测点与机柜归属。

封闭冷通道：冷通道可新增多个分组，热通道固定一组，机柜挂在冷通道分组下。

封闭热通道：热通道可新增多个分组，冷通道固定一组，机柜挂在热通道分组下。

无封闭：统一就一个冷通道分组进行处理与展示，既可关联传感器，也可关联机柜，用于支撑非封闭机房的诊断。

关联传感器：在冷通道分组下关联的传感器，其实例上通道/位置类属性须选冷通道；在热通道分组下关联的传感器，该属性由系统自动置为热通道，与分组一致。

步骤1必审；本配置决定诊断粒度能否到通道/区域级。

关联模块：通用关联弹窗（触发入口：关联空调 / 关联传感器 / 关联机柜）

该弹窗复用同一套结构，根据触发入口切换标题、候选对象和已选对象列表，降低用户在不同配置区间切换时的理解成本。

左侧用于筛选和勾选候选对象，右侧实时展示已选结果；点击“确定”后回写到对应模块，点击“取消”或关闭按钮则不保存本次改动。

弹窗只展示当前机房范围内的对象实例，不跨机房混选；当用于分组配置时，用户在这里确认的是“归属关系”，不是修改对象本身属性。

由「关联空调」进入时，数据源为所选空间—机房下的设备，并在物模型维度过滤：仅末端空调物模型及其子模型下的实例出现在候选列表中。

由「关联传感器」进入时，候选仍按机房与温湿度物模型过滤；确认写入对应冷/热通道分组后，冷分组要求传感器实例的通道/位置类属性为冷通道，热分组则自动置为热通道。

交互说明 v2.9 产品推断

关联模块：「复制属性到同类型设备」弹窗；入口：空调设备信息每台属性区右上角「复制到同类型设备」（2026-10-31 新增）

  • 场景：同一机房同对象类型的空调大多是同一批同规格设备，配好一台后把属性批量复制给其他台，不用逐台填。
  • 默认：来源 = 点按钮的那台；勾选来源已填的全部属性；目标 = 同对象类型的其他全部设备；方式 = 只填空值。
  • 只在同对象类型间复制：风冷型只能复制给风冷型，冷冻水型只能复制给冷冻水型（属性集不同）。
  • 预览：底部实时显示「将填入 N 项、覆盖 M 项、跳过 K 项（已有不同值）」；没有勾选属性或目标、或没有任何变化时「确定复制」不可点。
  • 确定：关闭弹窗，目标设备属性区刷新，被写入的格标「已修改」，toast「已复制到 N 台：填入 X 项，覆盖 Y 项」；只改本页数据，随热力模型保存写回。
  • 取消 / ×：关闭弹窗，不做任何修改。
