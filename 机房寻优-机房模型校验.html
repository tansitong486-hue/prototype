需求说明 v2.9 需求文档

页面级：让实施在机房热力模型上线寻优前，看清每台空调能否被仿真寻优动作、为什么不能，以及机房拓扑是否完整。

  • 覆盖场景：新建保存后首次校验；去物模型补属性 / 补绑点 / 改关系后重新校验；编辑模型后结果过期再校验。
  • 本期不覆盖：不在本页修改任何属性、绑点或关系（只读 + 跳转去维护 / 去配置）；不做定时自动校验与告警推送；不校验仿真精度（精度看「仿真验证」页）。
  • 与寻优的关系：寻优每轮按同一规则表逐台判定，本页结果不是寻优的开关；未校验的模型照常寻优（产品推断）。
提示

1、模型校验按每台空调的对象类型，检查仿真寻优所需的物模型属性、写点与组件实例是否齐全、是否与运行数据一致，并检查机房供冷 / 换热 / 回风关系是否完整。

2、ERROR 的空调会移出可动作集（寻优时保持当前控制不动作），其余空调照常寻优；拓扑不完整时机房寻优跳过。WARN 只提示，请实施核对。

状态说明 v2.9 产品推断

关联模块：校验结果横幅（三态互斥 + 校验中）

  • 通过（绿）：无 ERROR；有 WARN / 无法校验时标题写「校验通过，有 N 条提示」。描述带可动作集台数与校验时间。
  • 有设备移出（橙）：有设备级 ERROR（INPUT_MISSING）但可动作集不为空、拓扑完整：「校验完成：N 台移出可动作集，机房不阻断」（缺数据处理）。
  • 阻断（红）：拓扑完整性 ERROR（TOPOLOGY_INCOMPLETE），或投入空调全部 ERROR / 全部投出（可动作集为空）：「校验未通过：机房寻优将跳过（SKIPPED）」（§7.2「拓扑不完整 → 机房本轮 SKIPPED」）。
  • 校验中（蓝）：点「重新校验」后横幅变「校验中…」，按钮置灰；完成后刷新横幅、统计和两张表，toast「校验完成」。
  • 未校验或已修改：模型保存后从未校验，或校验后模型被编辑，进入本页自动执行一次，不展示旧结果。
  • 校验失败：取数超时等系统原因时横幅显示「校验失败，请重试」，保留上一次结果不覆盖（原型不演示）。

交互说明 v2.9 产品推断

关联模块：校验明细 — 筛选、去维护、去配置、重新校验

  • 筛选：级别（全部 / ERROR / WARN / 无法校验 / 已校验）、实例（全部 / 各空调 / 机房拓扑）、按属性或说明关键字搜索、「只看问题项」（隐藏已校验行）；条件即时生效，不需点查询。总览「查看明细」= 实例筛选设为该台并滚动到明细。
  • 去修改 →（属性类 ERROR，2026-10-31 调整）：属性已改为在热力模型配置步骤 1 页内直接填写，故跳「编辑机房热力模型 › 步骤 1」并展开、定位到该设备该属性格；URL 带 return=机房寻优-机房模型校验.html?room=…，保存后回到本页并自动重新校验。不再跳设备管理。
  • 去绑点 →（写点 / 证据源类）：测点绑定仍在「工程配置 › 设备管理 › 该实例 › 测点绑定」，带同样回跳。controlMode 与写点不一致时两个入口都给：「改控制型 →」（步骤 1）或「去绑点 →」。原型均只 toast。
  • 去配置 →（拓扑 ERROR）：跳机房热力模型编辑态步骤 2 并定位到对应冷点 / 通道分组 / 空调回风行，带同样的回跳参数；保存后回到本页自动重新校验。原型只 toast。
  • 重新校验：按当前数据重跑全部校验项（含拓扑），完成后刷新横幅、统计和两张表；校验中按钮置灰防重复点击。
  • 返回：面包屑「机房热力模型」或标题左侧 ← 回列表。
边界与异常 v2.9 待确认

关联模块：校验明细 — 口径待确认项

  • controlMode 与写点不一致的原因码：§4.3 只定级别 ERROR 未定码，原型按「缺少该控制型必需的写点」归入 INPUT_MISSING，评审定是否单列。
  • 未校验能否寻优：原型按「能，寻优每轮自己判」处理；若要求「校验通过才能绑寻优」需另加门槛（未画）。
  • 运行中设备：ERROR 设备若运行中且物理量无法估计，寻优整轮 SKIPPED（§六）；本页是静态配置校验，不判运行态，只在横幅描述里提示。
  • 空态：模型未关联空调时本页只出拓扑校验与「尚未关联空调」，机房结论为阻断。
  • 回风关系必配的判定属性（2026-11-02）：「封闭热通道」读空调组 aisleSealedMode（后台三档，标准物模型表需补「封闭热通道」）；「行间 / 列间」暂读后台 DTDL 已有的精密空调 placement_position（标准物模型表与需求文档未收录），底座式视为房间级、未填按房间级，均待确认。0_100 验证机房 11 台该属性全为「行间」、疑似缺省，按此规则会报回风关系未配。
