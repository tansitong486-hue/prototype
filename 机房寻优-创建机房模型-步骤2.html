字段说明 v2.9 需求文档

关联模块：热通道传感器与空调的回风关系（2026-11-02 新增）

  • 空调末端（只读行）：步骤 1 已关联的精密空调都列出，包含投出空调；一台一行，与供冷关系表同序。AI 是否调节由投入 / 投出决定；新风机、加除湿器不出现。

  • 必填：表单不强制，「完成」不拦；按必配规则在「机房配置校验」页校验（见下方数据逻辑）。

数据逻辑 v2.9 需求文档

关联模块：回风关系 — 关系类型、仿真用途、必配规则

  • 关系类型（复用，不新增）：每选一个热点存一条 dtdl:asset:THSensor::feedsAir 边，起点 = 热通道温湿度传感器（热点），终点 = 空调。与换热关系（冷点 → 热点）是同一关系类型，按终点对象区分：终点是温湿度传感器 = 换热，终点是空调 = 回风。关系记录不加字段、不填权重。
  • 回风来源通道：每台空调所连热点所属的通道，就是它的回风来源通道。
  • 仿真怎么用（以《末端机房仿真模型》为准）：仿真回推每台空调的回风时，取本机回风来源通道的排风温度加权：已配置回风关系，取所连热点所属通道的排风温度等权平均；未配置，按该台对各通道的供风份额加权，即供气对称。每台另有回风入口偏差（回风读数与回推回风之差），每轮按实测重算。回风关系只回答「这台空调从哪些通道回风」，不填权重。
  • 必配规则：机房通道封闭模式 = 封闭热通道（空调组 PrecisionACGroup.aisleSealedMode = 1，即步骤 1「通道封闭模式」）时，组内每台参与寻优的空调至少要有 1 条回风关系。封闭冷通道机房可不配，未配按供气对称。无封闭机房没有热点，本段隐藏、不校验。
  • 在哪校验：「完成」不校验；保存后在「机房配置校验」页随拓扑完整性一起执行，必配未配记 ERROR TOPOLOGY_INCOMPLETE（逐台一条，机房本轮 SKIPPED）；处置「去配置 →」跳回本页编辑态，定位到该空调的回风行。
边界与异常 v2.9 待确认

关联模块：回风关系 — 待确认项

  • 封闭热通道取值：后台 aisleSealedMode 有 0 封闭冷通道 / 1 封闭热通道 / 2 无封闭三档；标准物模型表该属性只写了「封闭冷通道 / 无封闭」，需补「封闭热通道」。
  • 关系的目标对象：后台 THSensor::feedsAir 现定义的目标对象是温湿度传感器，回风边的终点是空调，需后台把目标放开到末端空调（同一关系类型扩目标，不是新增类型）。
  • 「所属通道」口径：原型按「热点的换热入边来自哪些冷通道」理解（与热点关联通道权重 w(h,A) 同一集合），不是热点所在的热通道分组——封闭冷通道机房热通道只有一组，按分组理解则所有空调来源通道相同。
  • 来源热点投出（产品推断）：投出热点的回风边不参与；空调因此没有有效回风边时按未配置处理，必配时在校验页报出。
