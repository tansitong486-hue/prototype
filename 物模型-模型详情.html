需求说明 v2.5 需求文档

本页是做什么的：看一个物模型（一类对象）的完整定义。本期在原有「属性 / 测点」之外，补上第三类定义——对象指标，回答「这类对象有哪些指标」。

  • 支持的场景：①产品与实施核对某类对象应该有哪些指标；②排查「页面上某个指标没出现」时，先在这里确认类型层有没有这条指标。
  • 两层分工（需求 6 §7.2）：本页是物模型层——只讲「这类对象有这些指标」，不显示任何指标值；某个具体对象「现在能不能算、值是多少」属于实例层，在《能效视图》节点详情的「指标列表」里看。
  • 本期不覆盖：不开放现场向物模型配置指标（变更只随标准包升级发布）；不做自由公式指标；不产出「该模型全部实例的合计 / 平均」这类模型级聚合值。

边界与异常 v2.5 需求文档

关联模块：测点 Tab —— 与「指标」Tab 的边界（重点，评审必看）

  • 两个 Tab 是两条独立链路：测点是物模型上的数据槽位；指标是指标工厂里的口径定义。需求 6 明确不在物模型上新增测点，指标不会占用测点槽位。
  • 同名不等于同一个东西：本 Tab 里已有的「实时 PUE 1_107_0」等能耗 / 能效槽位（含 POE、CF 这类别名）是历史既有能力，指标工厂既不回写也不读取，算法与配置方式保持原样。它和「指标」Tab 里的 PUE 数值不一致不算缺陷，排查时不要互相对数。
  • 为什么指标不能塞进测点：能耗用量、分时成本这类指标带「时间跨度 + 能源类型 + 计费时段」入参，一个单值测点槽位在结构上承载不了；按粒度铺虚拟测点会造成测点爆炸。

需求说明 v2.5 需求文档

关联模块：指标 Tab（本期新增）—— 这类对象有哪些指标

  • 解决什么问题：过去「哪类对象有哪些指标」散落在代码和各页面的对象类型白名单里，谁也说不清。本期收回到物模型上定义一次，该模型及其继承子模型的实例自动具备，新建实例即刻生效。
  • 本 Tab 只回答一件事：这个模型上有哪些指标。不回答「某个对象现在算不算得出」「值是多少」——那是实例层的事，在《能效视图》节点详情的「指标列表」里看。
  • 只读：指标由产品预置、随 KE 标准包发布，现场与实施不可新增、不可改口径，因此本 Tab 没有新增 / 编辑 / 删除入口。
交互说明 v2.5 需求文档

关联模块：指标列表

  • 一行一个指标：列表直接列出这类对象可用的具体指标（如电能消耗量、用水量、尖 / 峰 / 平 / 谷时电费），与下游选择器里能勾到的选项一致，不需要再选参数。
  • 分两组：实时值指标按默认调度计算后形成时序历史，实例层可查当前值与历史曲线；统计指标按起止时间查询时计算。
  • 筛选：关键字（指标名称 / 标识）与业务分类，输入即筛选、清空恢复全部。
  • 只读：不提供新增 / 编辑 / 删除，也不提供逐条的口径详情弹窗；要看某条指标的实际取值，去《能效视图》选具体对象。

状态说明 v2.5 需求文档

关联模块：指标列表空态

  • 该模型没有指标：显示「该物模型上没有对象指标」，并说明能耗 / 成本类指标在空间、集合、资产三棵继承链上，能效指标在园区、数据中心单元与暖通空调 / 电力 / 其他系统上——不是缺陷，不需要现场处理。
  • 筛选无结果：显示「没有找到匹配的指标」，保留筛选条件不自动清空。
  • 不展示指标值，也不展示「可算 / 待配置」：这两者都是实例层状态，本页只回答「这类对象有这个指标」。
边界与异常 v2.5 需求文档

关联模块：指标清单的构成规则（评审重点）

  • 清单含继承：列表是本模型自己定义的 + 沿继承链从父模型拿到的，合在一起展示，不区分来源；同一条指标不会在父子模型上重复定义。
  • 同名两条不是重复：PUE 这类能效指标会同时出现实时和统计两条，靠「时间查询」列区分。
  • 条数随工程变化：各能源的消耗量、各时段电费是按当前工程已启用的能源与计费档位列出来的，换一个只用电的工程条数会更少。
  • 与「测点」Tab 不互通：指标不占用物模型测点槽位，与测点里同名 / 别名的 PUE、POE、CLF、CF 等既有槽位互不回写、互不读取，两个数不一致不算缺陷。
