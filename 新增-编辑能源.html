版本信息

当前版本：v2.5

更新日期：2026-07-24

变更概述：能源类型的原「能源单位」明确为「累计量单位」，新增必填「实时值单位」；累计量单位服务尾值差、计费和历史统计，实时值单位服务瞬时量测点与当前值指标。预置电为 kWh / kW、水为 m³ / m³/h、冷量为 kWh / kW。能源类型测点同时由「仅累积量」扩展为「累积量 + 瞬时量」成对定义，并明确物模型继承生效范围。

数据逻辑 v2.5 需求文档

关联模块：「计量测点」表格（累积量 + 瞬时量成对；表具口径）

  • 成对定义：每个能源类型下按物模型配置 =（物模型 + 累积量测点 + 瞬时量测点）。例：电 → 累积量「正向有功电能 / 有功-总」、瞬时量「有功功率-总」。
  • 单位对应：累积量测点使用基础信息中的「累计量单位」；瞬时量测点使用「实时值单位」。两套单位分别配置，不从测点名称或另一套单位自动推导。
  • 表具定义：命中累积量测点定义的物模型实例（含继承匹配）= 一块计量表具；表具在该能源类型下对应唯一累积量测点，并带成对瞬时量测点。
  • 物模型继承：子物模型可继承父模型测点。配置在父模型上的测点对，对继承了该测点的下级子物模型实例同样生效，无需按子模型重复配置。
  • 父 / 子互斥：已配置父物模型时，其下级子物模型不可再选；若先配子模型再配父模型，系统自动移除冲突的子模型行（或保存时拦截）。
  • 自动生成明细：v2.5 起系统对全部命中累积量定义的实例自动生成表具半小时能耗明细（无论是否绑定计量对象、是否应用计费方案）。瞬时量不进核算归档，供拓扑建立后对象侧查询瞬时功率。

交互说明 v2.5 需求文档
  • 新增测点：追加一行，依次选择物模型、累积量测点、瞬时量测点（示意）。
  • 成对必填：同一行累积量与瞬时量均必填；保存时校验二者同属所选物模型（或其父模型继承测点）。
  • 父 / 子互斥：已选父物模型时，其子物模型下拉项置灰并标注「父模型已配置」；选父模型时若已存在子模型行，自动移除并 toast 提示；保存时再校验一层。
  • 删除：移除该行；至少保留一行有效配置（示意未强制拦截）。
  • 物模型 / 测点：下拉级联；物模型仅限资产、集合类型；测点下拉展示该物模型自有及继承自父模型的可读测点。
  • 继承生效：配置父模型测点后，其子模型实例自动命中，列表无需为每个子模型再加一行。
交互说明 v1.0 引用自古典原型
  • 新增测点：追加一行，物模型 / 测点待选（示意）。
  • 删除：移除该行；至少保留校验由产品定义（示意未限制最少行数）。
  • 物模型 / 测点：下拉级联，物模型仅限资产、集合类型（实现侧约束）。
