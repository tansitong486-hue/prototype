需求说明 v2.4 需求文档

关联模块：多工况探索 — 策略制定（阶段一）

「多工况探索」是 v2.4 新增的独立功能模块，目标是在受控、安全前提下主动驱动冷站走到被动运行走不到的稀缺工况，为模型训练补充样本。模块内分三阶段：策略制定（本页，离线编排，不下发不动设备）→执行（按已生成并保存的执行计划连续下发 + 运行稳定后记录）→验证（训练完成后对比预测值与实测值，不保存）。策略归属创建时选定的目标系统（本页演示：3#数据中心水冷冷水系统），本页只读展示。

本页覆盖：确定开机组合与绑定安全边界/仿真模型、按设备类型（设备类型）手动录入基准线并做边界校验、配置调整步长生成执行计划（生成时按历史数据比对自动排除已覆盖点）、执行计划清单审核勾选与保存草稿。

本期不覆盖：设备开关机 / 加减机探索；基准线自动求解；执行下发与运行稳定（见执行监控页）；验证对比展示（见验证对比页）。

数据逻辑 v2.4 需求文档

关联模块：④ 执行计划清单 — 历史数据比对自动排除规则（生成执行计划时后台自动执行，界面不常显）

  • 取数：对每个执行计划点，查被探变量对应测点近 T = 90 天历史数据（项目级可配）。
  • 邻域窗口：以执行计划点目标值 v 为中心，取 v ± 半个调整步长为邻域窗口（如步长 2Hz、目标 34Hz → 窗口 [33,35)，各点窗口互不重叠、无缝覆盖）。
  • 稳态过滤：窗口内仅统计稳态样本（复用三层预处理稳态筛选口径）。
  • 判定与排除：窗口内稳态样本数 n ≥ N_hist = 20 → 判"已覆盖"，该工况点在生成执行计划时被自动排除，不出现在④执行计划清单中，仅计入汇总条"已自动排除 N 个历史已覆盖工况点"；n < 20 → 判"空白/稀疏"，保留进清单。
  • 人工复核：④执行计划清单每行展示历史样本 n 值（保留的点均为 n<20 的稀疏点），供审核复核。
  • T、N_hist 均支持项目级配置覆盖，不叠加开机组合一致性过滤。

被探对象 / 控制变量只读文本——按设备类型写，并注明同时下发的开机实例（如"冷冻泵（1号、2号、3号 同时下发）/ 频率"）同类型所有开机实例同时下发相同设定值，不逐台单独排步
批次内序号只读数字——批次内从 1 递增对应"批次内第 n 步"
目标设定值只读数字——基准值 + 累计补偿如"34.00 Hz""8.50 ℃"；按设备类型统一，一步对同类型全部开机实例生效
补偿 / 步长只读数字——取③对应设备类型步长往上方向为正、往下方向为负
历史样本 n 值只读数字标签——如"n=5"保留进清单的点均为 n<20 的空白/稀疏点，展示 n 值供审核复核；排除规则见上方数据逻辑批注
安全边界校验只读状态标签—通过 / 越界通过（生成逻辑保证不越界）若因边界配置变更等原因出现"越界"，该行不建议勾选执行，需回到②③调整后重新生成
稳态等待条件只读文本——"停留≥15min且温度稳定"对应需求 8.3 运行稳定的最小停留时长
单步预计时长只读数字——25 分钟 / 步（示意）汇总为批次 / 总预计执行时长，展示于表格上方汇总条
交互说明 v2.4 需求文档

关联模块：④ 执行计划清单与保存

  • 全选：勾选清单内全部行。
  • 清空勾选：取消清单内全部勾选，便于反向少量勾选。
  • 保存草稿：点击后保存当前执行计划与勾选状态，toast 提示"已保存草稿，可随时回来继续编辑或发起执行"；草稿可反复编辑。
  • 发起执行：跳转 多工况探索-执行监控.html；前提是执行计划已生成并保存，能否执行只看这一条件。发起执行后执行计划锁定，不可再修改（来源：产品推断）。
  • 草稿态下可反复调整①②③后重新生成执行计划（④刷新），发起执行前均可修改。
数据逻辑 v2.4 需求文档

关联模块：④ 执行计划清单与保存 — 汇总条

"共 N 步" = 执行计划清单总行数（历史已覆盖点不计入，已在生成时排除）；"已自动排除 M 个历史已覆盖工况点" = 生成执行计划时被自动排除的点数（固定值，不随勾选变化）；"预计总时长"与"拟执行 K 步" = 当前已勾选（拟执行）行的数量与"单步预计时长"累加，随勾选状态变化实时重算。

边界与异常 v2.4 需求文档

关联模块：④ 执行计划清单与保存

  • ②中任一行基准值越界或未录入，均不可生成执行计划；基准值越界不可生成执行计划。
  • 执行计划清单中若存在"安全边界校验 = 越界"的行，需回到②③修正后重新生成，不建议强行勾选执行。
  • 草稿可反复编辑，发起执行后执行计划锁定，不可再修改；如需调整需发起新的策略草稿（后半句来源：产品推断）。
  • "发起执行"仅在执行计划已生成并保存后可用，重复点击的幂等处理由执行监控页负责。
