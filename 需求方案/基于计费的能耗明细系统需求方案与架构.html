核心结论

一条主链、一个事实源： 累计读数先生成与拓扑无关的表具核算明细并归档；对象查询指标由指标工厂沿当前计量拓扑在每次查询时计算。C1 实时能耗值与 B1–B5 能效实时值沿用数据工厂现有计算指标调度，计算后像测点一样写入时序存储，形成当前值与历史曲线；表具核算明细仍是用量与成本的唯一事实归档，实时指标历史是可重算的派生时序结果。

阶段 核心计算 数据归宿 变化后的处理
累计量 → 表具核算明细 尾值差、数据质量校验、人工修正、计费属性 表具事实层，半小时 / 时 / 天 / 月 按表具和时间窗幂等重算
表具核算明细 → 对象指标 沿计量拓扑递归 Σ输入 − Σ输出、能效比值 查询指标按自身查询参数即时计算；实时指标计算后写入时序存储 查询指标在下次查询时按时间段所属拓扑版本出数；某版本内容变化后自动重算受影响实时指标在该版本已生效区间内的历史并原子替换（§4.5）

本版边界

  • 本册按六个交付包编号：需求 1–5 构成能源计量核算与指标生产链，需求 6 为面向选择器的指标选取服务；需求 7–13 的页面消费、总览看板与平台侧选择器扩展在关联文档中维护。跨文档引用优先使用需求名称。
  • 不新增表具或计量对象主数据，不自建对象层查询服务，不做估算补值、账单封存和自由公式指标。计量拓扑按能源类型做生效版本管理（§4.5，2026-08-26 增补），支撑配电线路技改场景。
  • 实时值按数据工厂默认调度计算并写入时序存储，支持当前值与历史曲线；查询指标按查询时间段所属拓扑版本和查询参数即时计算、结果不物化。
  • 指标定义按物模型（类型）注册、按实例自动派生；下游可按物模型或按实例两种方式选取同一指标。不在物模型上新增测点 / 属性，不做模型级聚合值（同一物模型全部实例的合计 / 平均）。
  • 页面统一消费指标工厂产出；「表具能耗明细」管理页例外，直接读取表具事实层。

版本价值目标

从用户场景看，本版要解决三件事。

  1. 数要准，理论可达 100%。以前直接拿累计值做差值，中间一旦有脏数据、跳变或通讯异常，能耗和能效都会算错，这不可接受。本版支持数据治理，能识别和过滤异常数据；数可审计，能手改、能批量重算，用多种方式把最终数据做到 100%。
  2. 配得快，单项目实时配置一天内完成。以前每类测点逐个配公式；现在批量配好计量关系，能耗、成本、能效的实时和累计指标自动出来。
  3. 可用性大幅提升，不量化。能效能耗管理的使用体验比旧版完整得多，具体是：
    1. 可以算成本了，以前没有。
    2. 可以做多类指标的对比和趋势分析，比原先只做能耗量对比有巨大提升。
    3. 看板样式和内容更丰富，有了评价指标，用户不但知道能效，也能感知处在什么水平。
    4. 和报表、组态做了深度打通：不只在能效应用里能用，基础报表和组态也能灵活配置，按不同样式给用户定制呈现。

3.2.1 时间槽、尾值与封口契约

为保证同一批原始数据在自动生成、人工触发重算与不同服务节点上得到一致结果，半小时明细统一执行以下时间契约：

  1. 时间槽边界：项目时区为业务切分时区，半小时槽统一使用左闭右开区间 [T, T+30min)；数据时间恰好等于 T 的样本属于本槽，恰好等于 T+30min 的样本属于下一槽。底层统一存 UTC，槽归属、分时计费和自然日 / 月 / 年边界均按项目时区解释。
  2. 只认数据时间：样本归槽与尾值排序使用设备数据时间，不使用接收入库时间；接收入库时间只用于同数据时间版本去重与迟到识别。乱序到达的样本先按数据时间归槽，再参与该槽重算。
  3. 尾值有效窗口：从测点已有采集配置读取标准采集周期 Δ，系统计算尾值有效窗口 W = min(30min, max(10min, 2 × Δ))；取不到采集周期时 W = 10min。槽尾值只在 [T+30min-W, T+30min) 内选择数据时间最晚的有效累计读数；只有更早样本时按「尾值缺失」处理，不以陈旧读数冒充槽末值，也不跨槽借值。
  4. 确定性去重后再判有效：同一表具、同一唯一累积量实际测点、同一数据时间存在多条记录时，先取接收入库时间最晚的版本；若接收入库时间仍相同，取稳定记录 ID 最大的一条。只对去重后保留的版本做有效性判断；该版本为非数值、无数据时间或已被采集层标记无效时，不得回退使用更早版本，也不得作为尾值，保证失效修订与重复执行结果一致。
  5. 生成起点：表具首次启用、重新启用或更换唯一累积量实际测点时，从配置生效槽开始生成，首个有效尾值只作基线，不跨停用区间或测点切换边界计算差值。配置生效前的历史只通过「按时间范围重算」处理，不自动扫描。
  6. 初次封口：槽在 T+30min+W 首次封口并生成核算明细；此时仍无有效尾值则标记缺失。封口是调度与版本边界，不代表历史永久不可改。
  7. 迟到与补传：封口后到达、且数据时间属于历史槽 t 的有效样本，按晚到数据处理并触发幂等重算：重算 t、紧邻下一槽 t+1、受影响的表具时 / 天 / 月 rollup 与计费属性；人工修正锁定仍优先。每次封口或重算产生新的明细版本并记录触发原因、输入数据时间范围与完成状态。对象层无分片，下次查询读最新表具事实。
  8. 上层分片节律：半小时明细首次封口或重算成功后发布版本变更；表具 rollup 与指标工厂消费该版本事件推进。时 / 天 / 月分片在所属半小时槽全部完成首次封口后生成，迟到或修正数据再按受影响范围重算表具层，不另设一套独立的时间判断规则。对象层无分片，下次查询读最新表具事实。

3.3 多粒度归档（性能关键）

  • 表具核算明细归档为 半小时（基准）+ 时 + 天 + 月 多粒度，天 / 月 / 时由半小时累加生成，不重算差值；表具层归档粒度维持到月；对象层跨度查询时按入参粒度读对应表具归档分片再现场归集，其中「年」跨度读表具月分片累加（需求 5 §6.3.2）。
  • 目的：需求 5 形成对象月 / 年跨度结果时可读取表具月归档（如 100 块表 × 12 个月 = 1200 行），而非扫描半小时原子值，保证长区间查询轻量可承载。对象月 / 年结果仅随查询形成，不物化、不建立对象层分片。

3.4 幂等

  • 以 表具 + 能源类型 + 粒度 + 时间槽 为唯一键，支持指定时间窗重算覆盖（支撑晚到数据、坏值修正、人工修正、计费属性重算）。（表具在某能源类型下对应唯一累积量标准角色及实际测点映射，故键无需测点维度，见需求 1「表具口径」。）

3.5 数据质量校验（本期最小集）

取数：每个时间槽按 §3.2.1 的左闭右开边界、数据时间、尾值有效窗口与确定性去重规则选取尾值；不使用有效窗口外的槽内中间采样点。

差值：本槽用能量 = 本槽尾值 − 上一槽尾值（相邻相减，与 §3.2 一致；不跨槽取值）。

类型 规则 处理
尾值缺失 本槽或上一槽尾值取不到（离线 / 未上报） 该槽标记「缺失」，不产生有效用能量，不参与聚合；不作 0 处理，不跨槽追溯
单调性 本槽尾值 < 上一槽尾值 该槽标记坏值

坏值槽的尾值仍可作下一槽基准：数据质量标记作用于用能量（差值），不否定尾值本身的有效性。只要本槽尾值存在（非缺失），即可作为下一槽的减基准；下一槽差值再独立走本表规则（单调性 / 增量上限）判定。即：一个"差值超限 / 单调回退"的坏值槽不阻断其尾值参与下一槽计算——只有「尾值缺失」才不能作基准、才向后传递缺失。

断点续传（晚到 / 批量补传）：

  • 通信中断后恢复、历史累计值晚到或批量补传 → 先按数据时间归槽，再对受影响时间窗幂等重算（§3.2.1 / §3.4），按补全后的相邻尾值逐槽重算。
  • 重算范围要含缺口的相邻槽：补回槽 t 的尾值后，不仅重算 t 自身（t 尾值 − (t-1) 尾值），还要重算紧邻的下一槽 t+1（(t+1) 尾值 − t 尾值）——t+1 此前以 t 的缺失尾值为基准而被判缺失；同时重算首槽需读取缺口前一槽的尾值作为基准。
  • 补传后仍取不到尾值的槽保持「缺失」，并同步刷新受影响槽的下游 rollup 与成本。
  • 因相邻相减、不跨槽，重算不会产生"跨多个历史槽的超大差值"，无需对缺口做特殊阈值处理。

本期不做估算补值；坏值 / 缺失由人工修正（§3.6）或补传后重算处理。

3.6 人工修正

存在算错、需手动修正历史的场景，护栏如下：

  1. 采集原始累计值不可改（审计源头）；修正只作用在派生的表具半小时核算明细上。
  2. 每次修正留痕：操作人 / 时间 / 原值 / 新值 / 原因（选填；未填时留痕中原因记为「—」），并打「人工修正」标记（区别于正常 / 坏值）。新用能量必填，修正原因不拦截提交。
  3. 留痕可查看：半小时明细「数据质量状态」列中的「人工修正」标签可点击，打开留痕详情（操作人 / 操作时间 / 原值 → 新值 / 原因）；时 / 天 / 月行的「含人工修正」标签同样可点，展示区间摘要并提示下钻半小时查看逐槽留痕。不再仅依赖悬停 tooltip。
  4. 修正联动：修正表具半小时事实后，同步重刷该表具受影响的时 / 天 / 月 rollup 与成本属性；对象查询指标在下次查询时读取最新事实，实时指标不受表具用量修正影响。完整跨域影响见 §八。
  5. 幂等护栏（关键）：晚到数据触发的自动重聚合必须尊重人工修正值（人工值优先 / 锁定），不得静默覆盖；冲突时提示人工复核。
  6. 权限与流程：不设专用「修正角色」——具备「表具能耗明细」页面操作权限即可修正；不做二次确认弹窗、不接审批流，提交即生效。可追溯性由上述留痕、锁定与冲突提示承担，不额外加流程环节（本节第 2、6 条）。

4.3 关系校验

两类关系分别校验。新增、编辑、删除均须先校验，校验通过后方可保存。需求 1 的支持关系只约束新增与修改：取消「能源计量」或「供电」后，已生成关系继续有效；再次新增或修改时按当前支持关系筛选候选并校验。页面一次添加 / 删除双关系成员时，以一个用户动作原子提交两条独立关系。Excel 一行一个成员，用「关系类型」列区分能耗计量 / 供电 / 能耗计量+供电，含供电时再读同行「供电支路」；今日试算仍只读取能耗计量关系。

能耗计量关系：

  1. 表具唯一占用：同一 表具（含组件） + 能源类型 只能归属一个计量关系，输入和输出共用一个占用名额。
  2. 有向无环：禁止对象指向自身或形成环路；校验失败时返回完整冲突路径。
  3. 实例统一校验：设备实例与组件实例按各自实例 ID 参与同一套有向无环、父级唯一、重复覆盖和叶子展开校验；实例树父子层级不视为能耗计量边。
  4. 对象父级唯一：同一能源类型、同一计量方向下，一个成员对象只能有一个直接上级，不支持多父级分摊。
  5. 禁止重复覆盖：选择下级对象后，不得再选择其后代对象或已覆盖的叶子表具。
  6. 叶子展开校验：输入边记为 +1，输出边记为 -1。同一叶子的最终系数绝对值大于 1 时，判定为重复计量并返回全部冲突路径。
  7. 方向冲突：同一表具不得同时作为同一计量对象的输入和输出；相邻对象之间的上级输出、下游输入允许存在。
  8. 原子保存：校验范围覆盖当前对象及受影响的所有上级对象，校验以所编辑的拓扑版本为边界（§4.5.1）。批量操作任一项失败时整批不保存；历史查询继续使用既有拓扑。

供电关系：

  • 源对象所属物模型必须支持「供电」，源对象和目标对象必须有效；重复的同向关系不得保存。
  • 不执行表具唯一占用、计量方向、叶子展开和重复计量校验，也不修改能耗计量关系。
  • 源端为组件实例时，必须先通过 §9.2 U9 的平台关系接口能力确认。

4.5 拓扑版本管理（2026-08-26 增补）

面向配电线路技改场景（机柜单路改双路供电、列头柜新增机柜支路等），计量拓扑按能源类型做生效版本管理：不同时间段的能耗查询使用该时间段生效的拓扑关系。本节替代本章此前「不设置计量拓扑生效版本」的边界与 2026-08-25「维持原口径」的记录（§十一）。

4.5.1 版本模型

  • 每个能源类型一条独立版本时间线；版本是该能源下能耗计量与供电两类关系的整体快照，不做单对象独立生效日期。
  • 版本属性为生效日期（日粒度）加版本说明；生效区间左闭右开，自生效日起至下一版本生效日前一日。
  • 版本只能在时间线末尾追加：新版本生效日期必须晚于最新版本生效日期，允许早于今天（回溯生效），不支持在两个既有版本之间插入。
  • 版本状态由生效日期与当天推导：历史（已被更新版本接替）、当前生效、未来生效。全部版本（含历史）均可编辑：历史区间口径有误时直接在对应版本内修正，修改按 §4.5.2 重算；查看历史版本时页面展示编辑警示条，提示改动将重算历史数据。
  • 新建版本默认复制最新版本全部关系作为编辑起点；初始化时每个能源自动生成首个版本，默认生效日期统一为 2020-01-01（早于任何项目数据，覆盖全部历史区间），存量项目升级时以现有拓扑作为首版内容。
  • 版本删除：未来生效版本可删除（不产生重算）；当前生效版本在版本数大于 1 时可删除（二次确认）——删除后其生效区间由上一版本接管，生效日至今按上一版本拓扑重算；每个能源须至少保留一个版本，仅剩一个版本时不可删除；历史版本不提供删除。
  • 查重、方向冲突、成环等 §4.3 校验均以单个版本为边界；不同版本间同一成员可归属不同上级。

4.5.2 重算与出数

  • 任一版本内容变化（增删成员、修改方向、修改供电支路、Excel 整表替换）自动重算受影响对象的 C1、B1–B5 实时历史，重算范围为该版本已生效区间：当前生效版本为生效日起至今天，历史版本为其整个生效区间，未来生效版本不触发重算；沿用 §6.4 的原子替换、状态管理与失败重试机制。
  • 新建未来生效版本不触发重算，到生效日自动切换出数口径；新建回溯生效版本按其生效日起至今天重算。
  • 删除当前生效版本后，其原生效区间由上一版本接管，按上一版本拓扑重算生效日至今；删除未来生效版本不产生重算。表具层核算明细（需求 2 / 需求 4）与拓扑版本无关，不受任何版本变化影响。
  • 查询指标与实时历史按查询时间段所属版本出数：跨版本边界的时间范围按版本区间分段计算再拼接；某时间段无任何生效版本时明确返回「无计量关系」，不返回 0。

4.5.3 入口与兼容

  • 跨对象配置页提供版本切换、按最新版本复制新建和版本管理（版本列表、相邻版本对象级差异与版本删除）；控件布局与交互细节以原型批注为准。
  • Excel 导入导出均按各能源当前查看版本执行：任意版本（含历史）可导出、可作为整表替换目标，替换后按 §4.5.2 重算目标版本已生效区间。单对象「能效配置」入口本版仅读写各能源最新版本；今日试算按页面当前查看版本的拓扑执行。
  • 消费侧（能效视图、报表、组态等）无需感知版本，仍按对象 + 指标 + 时间查询；版本匹配与分段拼接由指标工厂在出数时处理。

6.2.4 内置指标适用与展示

  • 自动获得：内置指标随系统标准包部署到适用物模型，并对继承子模型生效；实例创建后自动获得指标入口，不逐实例配置。用户不可新增、删除或修改内置指标名称及计算口径。
  • 实时指标编辑：能效视图实时指标列表每行提供“编辑”，点击后在当前右侧区域进入与现网测点一致的编辑详情，保留基础设置、高级设置和告警配置；返回或取消后回到原列表。名称、指标标识、类型、单位、数据来源和计算口径为内置只读定义，别名、输入提示及告警配置可按实例维护。
  • 不提供赋值设置：实时指标由指标工厂按默认调度计算并写入时序存储，不允许通过测点编辑页的人工值、固定值或表达式赋值覆盖，因此实时指标编辑详情删除“赋值设置”。查询指标不提供编辑入口。
  • 适用范围：A1–A3、C1 对全部可作为计量对象或表具的空间、集合、资产类实例生效；B1–B5 仅对园区和数据中心单元生效，不下沉到暖通空调系统、电力系统或其他系统自身。
  • 状态判定：物模型只定义“有什么指标”，实例根据测点映射、计量拓扑和计费方案返回“可算 / 待配置 / 未计算”。
  • 本体与组件：组件使用组件自身实例 ID 计算和查询；设备详情只作为本体与组件指标的共同展示容器，不代表组件自动计入设备本体。
  • 不改既有测点：指标存在于指标工厂，不新增或回写物模型测点 / 属性；既有同名能耗、PUE、CLF 等测点保持原逻辑。

6.3 内置指标生成、查询与异常规则

6.3.1 内置实时指标

  • C1 与 B1–B5 实时值按数据工厂默认调度计算，支持读取最新值和已存历史曲线。
  • 每个实时指标结果返回指标值、数据时间和完整性状态；源测点缺失、无有效当前值或计算失败时不得补 0，也不得把旧值标成最新正常值。
  • 实时历史是瞬时样本序列，不替代基于表具核算明细的区间用量、成本和周期能效统计。

6.3.2 内置查询指标

  • 逐指标参数：每个查询指标按自身定义声明查询参数；能效视图在每一行展示该指标的参数输入。本期各指标均为开始日期和结束日期，后续可按指标扩展其他参数。
  • 统一触发：能效视图顶部只提供一个“查询”按钮，点击后收集当前列表中每个指标各自的参数并分别计算；首次进入查询指标时按默认参数自动查询一次，后续修改参数不会自动查询，须再次点击“查询”。
  • 无数据时间：查询指标是按参数即时形成的派生结果，不属于事实样本，不返回也不展示“数据时间”；实时指标仍保留样本数据时间。
  • A1、A2 与 B1–B5 周期值支持半小时及以上时间范围；A3 首版支持时 / 天 / 月。
  • 表具口径读取自身对应粒度的核算归档；计量对象口径按查询时间段所属拓扑版本（§4.5）读取版本内下级表具的对应归档后现场汇总，跨版本边界分段计算再拼接，无生效版本的时间段返回「无计量关系」。年查询读取表具月归档累加。
  • 区间内存在缺失、坏值或人工修正时，结果分别返回“含异常 / 缺失”“含人工修正”等完整性标记。
  • 跨天、跨月和计费时段按项目本地时间判断；环比、日均、占比由消费需求定义，不在本期新增指标。

6.3.3 内置能效指标取数规则

  1. 园区 / 数据中心单元向下递归整棵对象树查找暖通空调系统、电力系统、其他系统及 IT 系统；不为系统自身生成 CLF、PLF 或 OLF。
  2. 同一分支首次命中目标系统类型后停止继续匹配同类型后代；不同兄弟分支的首次命中结果求和，避免祖先与后代重复计量。
  3. 分子或分母对象缺失、未启用对应能源计量、或依赖的 A1 / C1 不可算时，能效指标返回“待配置”，不得补 0。

九、风险与未决项

9.1 风险、技术债与边界污染点

  1. 事实与派生混层：触发为把实时或统计结果当事实；后果是计费与用量出现第二真源；护栏是表具事实只读、对象结果不得回写（需求 5 §6.1、§八）。
  2. 计费属性污染用量：触发为成本重算覆盖用量字段；后果是原始核算失真；护栏是成本属性族独立维护（§5.2）。
  3. 缺少幂等：晚到、补传或重复重算会生成多份事实；以 §3.4 唯一键覆盖并保留审计。
  4. 人工值被覆盖：自动任务覆盖锁定值会破坏审计；人工值优先，冲突提示（§3.6）。
  5. 计算与重算过载：深树、长区间和拓扑改绑会放大查询及实时历史重算；须按受影响范围分片限流并验证时延、吞吐和恢复（§6.4）。
  6. 时区口径分裂：不同服务使用不同日界或分时时段会产生金额差异；统一按项目时区切分、UTC 存储（§3.2.1）。
  7. 补传范围不足：只重算缺失槽会使下一槽及成本持续错误；重算须包含相邻下一槽和表具下游归档，跨域影响见 §八。
  8. 拓扑版本误用：历史版本开放编辑后，把线路技改当作纠错改进历史版本（历史归属被错误改写），或把纠错当技改新建版本（错误口径被保留）；护栏是重算严格限定在被修改版本的生效区间、历史版本编辑警示条与操作留痕、删除限当前生效版本且二次确认，实施与培训须区分「纠错改对应版本、技改建新版本」（§4.5）。
  9. 实时历史重算风暴：上层改绑或回溯版本可能影响大量 C1、B1–B5 历史；重算范围限定为版本已生效区间（§4.5.2），须先算影响范围，使用临时结果版本、幂等任务和失败保旧（§6.4）。
  10. 计量方向错误：方向反置会产生虚增或负值；结果不置 0并返回异常标记，实施期核对输入 / 输出（需求 5 §6.2.1）。
  11. 能力与实例关系混淆：模型能力变化若自动改实例关系会造成不可控拓扑变更；支持关系只筛选后续新增与修改的候选，已生成关系保持原样，需求 1 也不因已有拓扑反向拦截或提示（需求 1、§4.3、§4.4）。
  12. 两类关系混并：复合保存会造成计量与供电互相误删或误算；两类关系独立生命周期，supplyPower 不进入指标计算（§4.2）。
  13. 组件指标归属错位：将组件指标改写到设备本体会导致同名冲突和引用失真；始终使用组件实例 ID，父页面只作展示容器（§6.2.4）。
  14. 组件供电端点能力未证实：平台若不接受组件 ID，供电链路无法落地；开发前完成 U9 真实写入、查询与删除验证。
  15. 尾值时间语义不一致：改用入库时间、跨槽借值或绕过有效窗口会导致重算不一致；所有生成与重算共用 §3.2.1。
  16. 拓扑递归重复计量：只校验直接关系会漏掉多路径重复；发布前执行 §4.3 全图校验和叶子有符号展开。
  17. 数据工厂排期依赖：指标计算与选择服务若无平台底座，需求 5、6 无法交付；排期须与数据工厂能力对齐。
  18. 注册表与现场物模型不同步：继承链或模型 ID 被改动会导致指标漏算；提供“注册模型 → 命中实例数”自检并纳入出厂基线（§6.2、§八）。
  19. 指标与同名测点混淆：两条链路算法不同，数值可能不一致；指标侧标明数据来源，不读写物模型既有同名槽位（§6.2）。
