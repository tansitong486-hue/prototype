AI 节能 v2.5 — 指标工厂消费侧需求方案（存量页面 / 总览看板 / 平台数据项选择器）

版本：v2.5　｜　状态：初稿　｜　范围：需求 8–13。

本册说明指标工厂产出的能耗量、成本和能效指标，如何在能效管理、总览看板、报表查询、融合组态及存量报表模板中统一查询和展示。数据生产与指标计算规则见同版本另册《基于计费的能耗明细系统需求方案与架构》。

需求 10–12 的原型已嵌入对应章节，评审时可结合正文直接查看。

一、背景与文档定位

1.1 文档关系

AI 节能 v2.5 的需求分为两册：

  • 明细引擎册（需求 1–7）：说明能耗明细、成本和能效指标如何产生。
  • 本册（需求 8–13）：说明这些数据如何在能效管理、报表查询、融合组态和存量报表模板中使用。

本册只描述查询、展示和操作要求；指标定义与计算口径以明细引擎册为准。

1.2 统一消费原则

不同页面的入口和展示方式可以不同，但同一指标的名称、单位、统计口径和查询结果应保持一致。本期涉及的页面范围与需求分工见第二章。

1.3 总览看板定位

总览看板是 v2.5 面向能源管理员和管理人员的一屏总览入口，支持实时 / 历史两种全局视角。用户进入页面默认查看实时，用于掌握当前能效、能源瞬时量及其近期变化；切换历史后，按所选对象和时间范围查看周期能效（含折算指标）、成本，以及用量的趋势分析 / 流向分析。

页面以对象类型、指标注册关系、能源计量拓扑、计费方案和下级系统关系为输入，自动生成可展示内容；用户只负责选择视图、对象、指标类型、能源，以及时间段模式下的时间范围，不需要配置卡片。原独立菜单「能耗流向分析」不再作为侧栏入口，桑基能力落在「能耗趋势与流向」卡内 type「流向分析」。

二、指标工厂消费侧：需求 8–13 总览

本组需求的目标是让指标工厂产出的能耗量、成本和能效指标，能够直接用于现有页面、总览看板、报表和融合组态。用户不需要再依赖原始测点自行计算，同一指标在不同页面查询时应保持一致。

2.1 改造范围

需求涉及范围本期目标
需求 8用能对比分析、用能定额考核、节能分析现有页面统一使用指标工厂产出的能耗、成本和能效结果。
需求 9总览看板集中展示能耗、成本、能效、趋势和流向。
需求 10报表的“选择测点”弹窗除测点外，用户也可以选择适用的指标。
需求 11原始数据查询、运行极值查询在适用范围内开放实时指标；时段指标仍由参数查询承接。
需求 12融合组态变量树允许选择指标并绑定到适用的展示图元。
需求 13存量能耗日报表、月报表支持能耗量、成本以及电、水、冷量等数据，不再局限于用电量。

2.2 需求分工

  • 需求 8、9负责能效管理的页面展示和查询。
  • 需求 10、11负责报表场景中指标的选择与查询。
  • 需求 12负责融合组态中的指标选择和展示。
  • 需求 13负责存量日报表、月报表的名称、查询结果、单位和导出适配。

各需求可以按所属模块分别实施，但应使用同一套指标名称、单位和统计口径。需求 13 沿用需求 10 的数据项选择能力，不另做一套选择入口。

2.3 公共规则（需求 10–12）

2.3.1 指标与测点并列展示

  • 测点表示设备采集的原始数据，指标表示平台计算后的业务结果，两者在页面上应清晰区分。
  • 报表查询和组态展示可以选择指标；告警、联动、控制下发、数据补录等场景仍只允许选择测点。
  • 指标不转换成测点，也不提供“指标转测点”入口。

2.3.2 指标名称与展示

  • 指标分为实时指标和时间段指标，页面根据自身用途展示适用类型。
  • 指标名称应直接说明能源类型和计费时段，例如“电能消耗量”“用水量”“尖时电费”。
  • 名称和单位以指标工厂发布内容为准，报表、导出文件和组态展示保持一致。
  • 无法计算的指标按页面规则隐藏或标记为待配置，不显示虚假结果。

2.3.3 选择与使用规则

  • 指标展示在其所属对象下，使用不同于测点的图标或类型标签。
  • 搜索、已选数量和页面原有的数据量上限同时适用于测点和指标。
  • 同一对象下的同一数据项不能重复选择。
  • 指标停用或删除后，已引用该指标的查询方案或组态应明确提示失效，不静默丢失。
  • 不同页面只开放与自身查询方式相匹配的指标，具体范围见需求 10–12 各章节。

2.4 本期不做

  • 不在报表或组态中创建、编辑、删除指标。
  • 不让指标参与告警、联动、控制下发和数据补录。
  • 不提供指标转测点、指标血缘分析或模型级批量合计。
  • 不为存量能耗日报表、月报表另建一套数据项选择入口。

三、需求 8：存量页面统一消费指标工厂数据

本需求覆盖用能对比分析、用能定额考核和节能分析。三个页面统一使用指标工厂产出的能耗量、成本和能效数据；页面内部的控件、交互、字段、状态及异常规则以对应原型批注为准，本章不再重复描述。

3.1 原型（对照批注评审）

用能对比分析 需求 8 标准化指标对比、对象与时间段选择、结果导出
用能定额考核 需求 8 对象用量与定额对比、历史归属提示
节能分析 需求 8 节能指标、趋势、设备能效对比与每日明细

评审时点击各原型右下角“批注”查看详细规则；可使用原型卡片右上角“全屏查看”。

3.2 跨页面规则

  • 三个页面查询相同对象、指标和时间范围时，名称、单位和结果口径保持一致。
  • 历史区间按当前计量关系统计；坏值和缺失数据不按 0 计算。是否展示“含异常 / 缺失”标记，按各页面原型批注执行。
  • 原独立菜单“能耗流向分析”移除，流向能力并入需求 9 的“能耗趋势与流向”；“用能趋势预测”入口与页面下线。
  • 页面内不重新计算电价、能耗或能效，具体指标定义与计算口径以明细引擎册为准。

四、需求 9：总览看板

总览看板用于集中查看当前对象的能耗、成本、能效、趋势和流向。页面结构、筛选方式、卡片出现规则、图表交互、状态和异常处理均以原型批注为准，本章不再重复描述。

4.1 原型（对照批注评审）

总览看板 需求 9 实时 / 历史视角、能效指标、能耗趋势与流向、能耗成本

评审时点击原型右下角“批注”查看详细规则；可使用原型卡片右上角“全屏查看”。

4.2 补充边界

  • 进入页面默认查看实时数据；切换历史后按所选时间范围查询。
  • 看板内容根据当前对象可用的指标和能源类型自动展示，不提供卡片配置、隐藏或拖拽排序。
  • 原“能耗流向分析”不再保留独立菜单入口，统一由“能耗趋势与流向”中的流向分析承接。
  • 同一指标在总览看板与其他页面中的名称、单位和统计口径保持一致。

五、需求 10：报表「选择测点」弹窗

本需求扩展参数查询和查询方案配置共用的“选择测点”弹窗，使用户可在空间、容量、能效三种视图中选择测点或指标，并按数据项设置查询周期和统计方式。

5.1 原型（对照看批注）

报表-选择测点弹窗 本册内嵌原型 覆盖 需求 10 全部范围 ① 外层已选清单｜② 按实例添加｜③ 按模型添加｜④ 参数查询语义收敛

读法：原型顶部四个场景页签 ①②③④ 与下面 §5.2–§5.5 一一对应；视图角标的控件不依赖指标工厂、可先行交付，指标角标的控件等需求 6。

5.2 场景①：外层已选清单

外层「选择测点」弹窗只改两处，其余（批量删除 / 全部移除 / 分页 / 取消与确定）保持现状：

  • 新增「类型」列：取值“测点 / 指标”，保存、加载和查询时均应保持类型正确。
  • 标识列适配指标：测点显示测点标识，指标显示指标标识，不得把指标识别为测点。

其他约定：搜索框对测点与指标同时生效、结果按类型分组；指标与测点合并计入本页既有数据项上限（系统配置的表格 / 曲线最大查询参数），不为指标单开配额。

5.3 场景②：按实例添加

视图切换（左树顶部）

  • 新增视图下拉，固定三项：空间视图 / 容量视图 / 能效视图，顺序与节点-测点树一致；位置对齐原始数据查询左树的现有实现——视图下拉在最上、搜索框在其下，不另设计一套。
  • 未配置的视图置灰并提示先配置视图，不隐藏——隐藏会让实施误判为版本缺失。
  • 切换视图不清空已选清单：三视图是同一批实例的不同树结构，用户可在空间视图按位置选几个、再切到能效视图按系统选几个，两批合并提交；已选按「实例 + 类型 + 标识」去重。

指标叶子

  • 指标挂在对象实例上（园区 / 数据中心 / 系统 / 设备组 / 设备），树上表现为对象节点下与设备子节点同级同层的叶子——不套「指标（N）」分组节点、不新增层级，图标与测点可区分；不挂在组件或测点下。
  • 某对象下出现哪些指标由物模型 × 指标注册矩阵决定（§2.3.3），选择器不为具体对象类型写死分支。
  • 指标名称已含能源类型与计费时段（如「电能消耗量」「尖时电费」），勾中即已确定入参，不需要二次参数面板。
  • 固定仅有值：只展示算得出结果的指标，缺输入的不出现在树上；不提供「仅有值 / 全部」开关，也不提供业务分类筛选条。

5.4 场景③：按模型添加

三栏逐栏说明：

  • 第一栏：「选择空间」改为「选择对象范围」，新增同样三视图；范围解析按当前视图子树递归（含下下级）。现状只取直接子节点，在能效视图下会漏掉挂在系统实例下的设备实例。
  • 第二栏：空间视图下保持现状「选择设备分类」（IT 设备 / 场地设施 / 备品备件 / 软件 → 二级分类 → 物模型）；能效 / 容量视图下语义放宽为「选择对象类型」，以便按系统类型（暖通空调系统 / 电力系统等）批量选取。模型列表展示全部物模型，不按「所选范围内有实例 / 已注册指标」过滤；所选范围内该模型无实例时，批量添加不产出数据项并提示「所选范围内无该模型实例」。
  • 第三栏：「设备测点列表」语义扩为「数据项列表」，按测点 / 指标分组；默认展示该物模型上注册的全部指标（含待配置），便于按类型批量勾选，不提供展示范围开关。

按物模型批量添加指标：选定「范围 + 物模型 + 指标」后，一次性加入该范围内所有该模型（含继承子模型）实例的同一指标，与现有「某模型所有实例的对应测点」对称。

红线：只批量添加，不产出模型级合计值。批量添加得到的是「N 个实例 × 同一指标」的 N 条独立数据项，不是该模型全部实例的合计或平均。同一块表可能同时落在多个实例的计量拓扑内，跨实例合计会形成重复计量；横向汇总由用户在报表内自行处理。

5.5 场景④：参数查询语义收敛

时段类型指标是按时间桶计算的指标结果序列，不是原始采样序列，但多个子时间桶仍可继续做求和、平均值、最大值或最小值等二次统计。参数查询不得再用「选求和才返回值、选其他方式返回 —」代替真实聚合能力，而应按指标语义声明支持项。

5.5.1 时间桶与聚合定义

概念 / 场景规则
输出采样周期时段指标在本页只开放 1 小时 / 天 / 月 / 年；每个输出点分别代表一个小时、自然日、自然月或自然年时间桶，半小时及更细档位不在参数查询中开放。
子周期二次聚合所用的下一级可用时间桶：小时优先读取半小时分片，天读取小时值，月读取日值，年读取月值。若某指标首版最细只提供小时值，则小时桶内只有 1 个有效子周期，平均值 / 最大值 / 最小值均等于该小时值。
求和对子周期结果相加，只适用于具有可加性的用量与金额指标。不得用于 PUE / CLF / PLF / OLF / WUE 等比值指标。
周期值按整个输出时间桶重新归集分子与分母后再计算比值，例如日 PUE = 当日总电量 ÷ 当日 IT 电量。只适用于能效比值类指标，是其默认且正式核算口径。
平均值 / 最大值 / 最小值对子周期指标结果序列分别取算术平均、最大、最小；空值不参与计算，若桶内全部为空则返回「—」。结果须保留实际采用的子周期，避免把「小时 PUE 平均值」误读成「日 PUE」。
实时类型指标本页可选。采样周期与聚合方式与测点一致（全部档位、原有聚合方式均可）；数据需经查询计算后呈现，非直接读取时段指标结果。

5.5.3 选择、混选与结果展示

  • 聚合方式改为数据项级配置：每条已选数据项保存自己的聚合方式；加入时带出上表默认值，用户可在该数据项支持集合内修改。查询方案连带保存每条数据项的采样周期与聚合方式。
  • 批量修改：页面可保留顶部聚合控件作为批量设置入口，但只修改支持该方式的数据项；不支持项保持原值，并提示「已跳过 N 个不支持该聚合方式的数据项」。
  • 混选：测点、实时指标、用量 / 成本时段指标、能效比值时段指标可同时查询，各自按本行聚合方式出数，不再因全局聚合冲突返回整列「—」。
  • 禁用而非静默空值：数据项不支持的聚合方式在行内不可选并说明原因，例如周期 PUE 禁用「求和」并提示「比值指标不可相加，请选择周期值或子周期统计」。
  • 列名自释义：结果表与导出列名须包含聚合口径；平均 / 最大 / 最小还须包含实际子周期，例如「PUE（小时平均）」或「电能消耗量（日最大）」；周期值显示「PUE（周期值）」。
  • 质量与空值：沿用指标工厂完整性标记。平均 / 最大 / 最小忽略空子周期但继承「含异常 / 缺失」标记；无任何有效子周期才返回「—」，不得用 0 补齐。

5.6 查询方案配置

  • 方案需连带保存指标的粒度与聚合方式，加载时完整复原。
  • 仅含测点的历史方案保持原样可用，不做数据迁移。
  • 加载时校验引用有效性，失效项标记并提示具体缺失指标，不静默丢项、不显示为空值。

六、需求 11：报表节点-测点树

本需求在原始数据查询和运行极值查询的左侧树中开放可计算的实时指标；时段指标仍由参数查询承接，右侧查询区域保持现状。

6.1 原型（对照看批注）

报表-节点测点树选指标 本册内嵌原型 覆盖 需求 11 全部范围 ① 原始数据查询｜② 运行极值查询

读法：原型两个场景页签 ①② 与下面 §6.2、§6.3 一一对应；两页的左树规则相同，差异只在右侧查询区，见 §6.4。

6.2 场景①：原始数据查询

  • 左树只开放可计算的实时指标，指标展示方式沿用 §2.3。
  • 时段类型指标不展示：该页定位是原始采样值排查（单日 + 上一日 / 次日），时段指标已是聚合结果，接入会让「原始」口径失真。
  • 右侧保持现状：日期 + 上一日 / 次日 + 查询，结果表按测点时序展示。
  • 数量上限仍为既有的 10 个，指标与测点合并计入。

6.3 场景②：运行极值查询

  • 左树规则同 §6.2。
  • 右侧保持现状：日报 / 月报 / 年报 + 日期 + 查询，结果表保持最大值 / 最小值 / 平均值及发生时间结构，不新增「极值口径」列、不新增指标结果行。
  • 时段指标的极值诉求由参数查询（§5.5）承接。
  • 数量上限仍为既有的 50 个，指标与测点合并计入。

6.4 两页共用规则

  • 固定仅有值：算不出结果的指标不出现在树上；不提供「仅有值 / 全部」展示范围开关、不做置灰占位行。
  • 不新增「已选数据项」操作行：勾选即参与查询，不增加芯片条或清除条。
  • 右侧查询区样式、交互、规则一律不变：本需求不改分页、导出、图表切换等既有能力。
  • 树上挂载位置、搜索与去重按 §2.3.3（在时段指标过滤之后生效）。

七、需求 12：融合组态变量树

本需求在融合组态变量树中开放指标，使指标可绑定到适用图元，并按指标类型正确展示、刷新和提示失效。

7.1 原型（对照看批注）

融合组态-变量树选指标 本册内嵌原型 覆盖 需求 12 全部范围 ① 变量树选指标 + 图元绑定｜② 图元兼容矩阵

读法：原型两个场景页签 ①② 与下面 §7.2、§7.3 对应；刷新与失效规则见 §7.4，在原型里表现为图元底部的「刷新方式 / 数据截止时间」。

7.2 场景①：变量树与图元绑定

变量树

  • “测点”页签按 §2.3 展示可计算的指标；指标叶子可拖拽、可点选，与测点叶子交互一致。
  • 「变量」页签：指标可作为只读变量参与页面展示表达式（如 本月电费 / 预算），不得作为控制指令的输入变量。

图元绑定

  • 绑定入口沿用现有两条路径——从左树拖拽到图元，或选中图元后在属性面板「数据源」里选，不新增第三种入口。
  • 不同指标可绑定的图元范围及取值方式见 §7.3。
  • 历史时序绑定须持久化采样周期与聚合方式，不依赖运行时上下文推断。

7.3 场景②：图元兼容矩阵

7.4 刷新与失效

组态页是常驻大屏、按秒级轮询刷新，这一点与报表侧按次查询不同，必须单独定规则：

  • 时段指标「实时值」：按半小时粒度对齐刷新，图元显示数据截止时间；不得按秒级轮询反复打指标服务。
  • 时段指标「历史时序」：按绑定的采样周期整点对齐刷新，规则同 §5.5；图元显示数据截止时间。
  • 实时指标沿用固定周期刷新；测点的刷新逻辑完全不变。
  • 失效处理：打开组态时校验绑定有效性，失效绑定在画布与属性面板标记并提示具体缺失指标，不静默显示空值。

八、需求 13：存量报表模板（能耗日报 / 月报表）改造

落点：报表模板管理 → 通用报表模板。

目标：将原“用电量日报表 / 用电量月报表”统一更名为“能耗日报表 / 能耗月报表”，并支持按所选时间范围查询能耗量、成本以及电、水、冷量等数据。

8.1 现状与问题

  • 现有 4 个模板均以「用电量」命名，用户容易理解为只能查询电量。
  • 现有模板主要按原始累计读数计算时段用量，与平台统一的能耗明细口径可能不一致。
  • 模板名称、展示字段和单位未充分适配水、冷量、成本等数据项。

8.2 功能要求

改造项 要求
模板名称 「用电量日报表」更名为「能耗日报表」，「用电量月报表」更名为「能耗月报表」；两个版本的模板名称同步调整。
数据项选择 沿用需求 10 的选择能力，可选择测点或指标。指标范围包括能耗量、成本等时段统计指标，能源类型包括电、水、冷量等。
时间统计 按用户选择的时间范围和日报、月报对应的统计周期展示结果。相同数据项、相同时间范围在不同页面查询时，结果口径应一致。
展示与导出 保留现有参数区、表格和导出方式；数据项名称、数值及单位按实际选择内容展示，不固定写成「用电量」。成本指标展示对应币种单位。
数据更新 能耗明细发生补录或修正后，用户再次查询报表时应展示最新结果。

8.3 业务规则

  • 选择测点时，使用平台统一的表具核算明细结果；选择指标时，使用指标工厂的计算结果。
  • 同一张报表可查询不同能源类型的数据项，但每个数据项必须展示自己的名称和单位，不能统一标记为电量。
  • 若所选数据项单位不同，应分别展示，不能直接合计为一个总值。
  • 无数据、数据异常及查询数据量限制沿用平台现有规则。
  • 需求 10 负责提供测点和指标的选择能力；本需求负责模板更名以及查询、展示和导出结果正确。

九、后续跟进事项

以下事项不影响本需求文档定稿，在开发准备阶段继续跟进：

  2. 对象可选性能力排期：确认需求 8 所需的对象可选性判断能力能否同批交付；若不能，同步调整对应验收时间。
