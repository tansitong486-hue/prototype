版本信息 v2.9 需求文档

当前版本：v2.9

更新日期：2026-10-26

变更概述：v2.9 评审会确认取消文件导入，映射方式改为「通用映射 / 转写规则」；转写规则在策略内直接填写 ba-transcribe/2.0 JSON，支持填入模板、格式化、校验和下载当前配置。保存按钮保持可点，保存时自动按 §6.10 再校验一次，有错误则在输入框下方列出并中止保存；通过后整体覆盖该策略的独立规则，从下一轮寻优起生效。

本页说明：转写规则是平台标准能力，每个下发策略独立维护一份规则；页面不含项目定制逻辑。下发模式、混合规则、置信度规则和工单通知规则照常可选；开启转写后，各下发方式只下发 BA 设定点中寻优值与当前值不同的点及其联动组成员（需求文档 §9.2）。

展示口径：BA 设定点是群控系统设备上的平级测点；寻优记录、手动下发弹窗、工单和下发记录仍按原有「设备 → 测点」展示。转写规则的名称和版本号记录在每轮寻优记录里用于追溯，寻优页面不单独展示。

关联模块：下发模式（与冷站群控下发策略「转写规则」的关系）

  • 不受限制：选了转写规则后，手动 / 自动 / 混合下发和其他策略项照常配置，不强制手动。

交互说明 v2.9 需求文档

关联模块：冷站群控下发策略 — 映射方式与转写规则

  • 映射方式切换：选「通用映射」显示原 9 类寻优项映射；选「转写规则」显示 JSON 输入框。切换或关闭群控时先保留框内内容；若直接保存，先确认「已填写的转写规则将被清除，可先下载留存」，确认后清除已保存规则并从下一轮起回到原逻辑（需求文档 §10.2）。
  • 填入模板：空内容直接填入 ba-transcribe/2.0 标准示例；已有内容时先确认「将覆盖当前内容」。
  • 格式化：通过 JSON 语法检查后按 2 空格缩进重排；解析失败时在错误列表标出行号、列号。
  • 校验：按需求文档 §6.10 执行，结果常驻显示在输入框下方；通过时显示「校验通过，共 N 条规则」并列出不拦截的警告，不通过时逐条列错误。
  • 下载 .json：将当前内容下载为「<meta.name>-<meta.version>.json」；解析失败或缺字段时用「转写规则.json」（需求文档 §10.2）。
  • 保存：按钮保持可点。转写规则为空时提示「请填写转写规则」；非空时自动按 §6.10 再校验一次，有错误中止保存，通过才覆盖。编辑态改过规则时，保存前确认「新规则将从下一轮寻优起生效」（需求文档 §10.2）。
  • 原型演示：演示 JSON 语法错误（只列出行列）；演示语义错误（只列 RULE_FILE_DEMO_ERRORS 三条；示意：以 langfang-a-ba-v2.json 58 条为内容）。

边界与异常 v2.9 需求文档

关联模块：转写规则 — 内容校验

  • 校验内容（需求文档 §6.10）：① 结构：格式正确、必填项齐全，顶层只有 meta 和 rules，直通（FIXED）规则不带公式；② 写法：增量锚定 / 直取 / 平移按规定形态书写；③ 语法与类型：公式和条件能解析，条件为真 / 假、基准和增量为数值，分支带 ELSE，局部量只在本条规则内引用且不成环；④ 引用存在：设定点、公式里的测点、条件里的设备在本项目物模型实例里都能找到，挂钩的寻优开关存在；⑤ 条件码：条件只能用条件码，说明不能为空，按「开关 → 投入 → 工况」排序不倒序；⑥ 联动组：成员齐全，同组成员的条件和公式一致。
  • 校验失败：JSON 语法错误只列行号和列号；JSON 能解析后，规则错误列出规则序号、target、字段和原因。保存按钮保持可点，保存时自动重新校验，有错误则中止。
  • 格式：输入内容必须为 ba-transcribe/2.0 JSON（需求文档 §6.5）；编辑权限由研发确定。
  • 正在进行的一轮：保存新内容时，正在跑的那一轮寻优仍按保存前的规则转写，不中断（需求文档 §十）。
