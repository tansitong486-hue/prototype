数据逻辑 v2.4 开发对照

关联模块：寻优收益指标条 · 统一数据源

接口：本页「寻优收益」「控制策略 × 功率变化」「寻优记录明细表」三块 UI 均来自同一条寻优记录，不另调仿真接口。列表：POST /api/v2/xdayu/project/v1/projects/{project}/optimization_logs:list（source=OPTIMIZATION_GLOBAL_ONLY，按 tuner + scheduler=global_1 过滤）；详情：列表选中项的 OptimizationLog，核心字段 variable_records[]（见 log.proto）。切换顶部系统页签 / 寻优记录 ◀▶ / 刷新，仅换 mountSystem 或 log.name，重拉同结构记录。

寻优记录含义：一轮全局寻优 = 寻优器（如 L-SHADE）对 N 组候选控制向量各跑一次完整仿真（流程见 水冷冷水系统仿真模型_v2.3.xlsx / 风冷冷水系统仿真模型_v2.3.xlsx），在满足安全边界与外置约束的可行解中取目标函数最优的一条，写入该 log。每条 VariableRecord：real_value = 寻优触发时刻实测/基线；optimize_value = 最优可行仿真输出；name = {设备twin}_{标准测点id}（如 0_149_1_1159_0）；property = 标准测点 id；parent = 设备 twin；variable_type 区分控制/被控/扰动（见下）。

variable_type 使用：策略 diff 仅统计 CTRL_OPTIMIZING（参与寻优的直接控制量，对应仿真表「0：求解器参数输入 · 直接控制变量」）；CTRL_UNOPTIMIZED 参与「开机设备」前后集合（投出/未寻优设备）；系统级 KPI 取 CONTROLLED（仿真「被控变量」输出，如总功率、COP）；DISTURBANCE 仅明细表展示、不进策略卡。注意：回退 realtime_baseline 时可能出现 CTRL_OPTIMIZING 不变但 CONTROLLED（如 COP）仍变化——策略区判「无变化」、收益条仍展示数值，属口径差异而非前端 bug。

数据逻辑 v2.4 开发对照

关联模块：寻优收益指标条 · 各槽位取数与计算

以下 P_real / P_opt / COP_real / COP_opt 均从当前 mountSystem（如 0_493）在 variable_records 中按 property 匹配；找不到记录或 optimize_value 为空时该槽显示「—」。

  • 系统节能率：(P_real − P_opt) / P_real × 100，保留 2 位小数。其中 P_real = 系统对象 1_167_0 的 real_value，P_opt = 同点 optimize_value。仿真 xlsx step 4 定义：水冷为「水冷冷水系统·总电功率」、风冷为「制冷系统·总电功率」（= step3 全部开机设备 1_627_0 之和，含二次泵）。twin 取当前 mountSystem 对应系统实例（风冷勿误绑「风冷主系统」扰动对象）。仅当 P_real > 0 且 P_opt 有效时展示。
  • 系统功率 kW：主值 = P_opt；副文案「实际 → 寻优预测」= P_real → P_opt；Δ 徽标 = P_opt − P_real（kW，带符号）。测点：1_167_0。
  • COP：主值 = COP_opt；副文案 = COP_real → COP_opt；Δ = COP_opt − COP_real。测点：1_1900_0（仿真 step 4 = 总供冷量 1_1300_0 / 总电功率 1_167_0）。
  • 参数调整 / 组合变化：前端对策略卡数据源做 diff 计数（与下方「控制策略」批注同算法）：有变化的 CTRL_OPTIMIZING 数值参数组数 =「N 项」；有变化的「开机设备」组数 =「N 组」。不过滤 UI 勾选，始终全量计数。

最大调整提示行（#benefitHeadline）：① 若任一类存在「开机设备」集合变化（property=2_167_0 且前后开机集合不同）→ 展示该类名称 + 前后设备名列表；② 否则在全部 CTRL_OPTIMIZING 数值变量中取 score = |optimize − real| / range 最大者，展示「类名 + 参数名 + 设备名 + Δ + 单位 + 量程占比%」。range = 规则配置「安全边界」该变量上下限之差；缺省：频率类（1_1159_0）50 Hz，温度类（1_24_0）10 ℃，台数类（1_1982_0）取配置上限。①②皆无则隐藏整行。

右侧功率栏（分类总功率 kW）——两级取值（已对照仿真 xlsx + 物模型）：

  • 优先：若 log 含 mountSystem 级物模型分项（variable_type=CONTROLLED，不在仿真 xlsx 表内，属系统自动计算）：冷冻泵 1_1905_0、冷却泵 1_1906_0、冷却塔 1_1907_0、主机 1_1904_0（见实施期数据质量 B2-g）。
  • 降级：对该类全部设备实例的仿真 step3 输出 {deviceTwin}_1_627_0 分别取 real/optimize 后求和（停机实例功率通常≈0，仍计入求和）。
  • 板换：无上述两类数据源 → 固定「功率 —」。

展示：前 = real_value，后 = optimize_value，Δ = 后 − 前。占总节能 = round( max(0,前−后) / Σ各类 max(0,前−后) × 100 )（仅下降类出比重条）。守恒校验：使用物模型四项 1_1904~7 时，四卡 Δ 之和通常≈系统 1_167_0 的 Δ；若项目含二次泵（仿真 step3 有二次泵 1_627_0 但 UI 不单独成卡），差额=二次泵功率变化，属预期偏差。二次泵的 1_1159_0/2_167_0 若在寻优范围，计入策略 diff 计数但不单独成卡。

展开/压缩：类内任一组（开机或数值）有变化 → 展开卡 + 左侧蓝条；否则压缩单行「无变化 + 功率维持 {real} kW」。板换类若项目无实例或本轮前后均无开机 → 备注「未启用」。

变化判定：数值 |optimize − real| < 0.005 视为未变；开机集合完全一致视为未变。语义色：控制 Δ 中性蓝；功率/COP/节能率绿降橙升；投入/退出标签绿/红。

需求说明

关联模块：冷站全局寻优规则配置 —「寻优目标偏好」

多目标加权寻优配置对应目标函数 J' = P_norm × (1 + γ(置信等级)) + min(λ₁·C_safety + λ₂·C_switch + λ₃·C_swing, C_max)。

  • 安全余量偏好（λ₁）：0.00～0.50，默认 0.10；越大寻优结果越远离安全硬边界。
  • 设备切换容忍度（λ₂）：0.00～0.50，默认 0.15；全局寻优涉及设备启停，本页可用（柔性寻优页置灰）。
  • 参数平稳偏好（λ₃）：0.00～0.30，默认 0.05；全局寻优为单时刻快照式求解，不涉及时序平稳性，本页置灰不可用，默认 0（柔性寻优页可调）。
  • 低置信保守度 γ(低)：0.00～0.10，默认 0.03；低置信候选需额外多省约 γ×100% 的电才会被推荐。

γ(低)=0 且三项权重均为 0 时行为与原单目标最小功率等价（向下兼容）。
